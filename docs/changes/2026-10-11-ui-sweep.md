## Theme ownership

`ui_tokens.css` owns the dark slate surfaces, teal accent, readable foregrounds,
border colors, typefaces, radii, shadows and scrollbar colors. `ui_shell.css`
applies them to the page chrome, menus, controls, panes and palettes.
`entry_pages.css` owns login/welcome; `admin_theme.css` maps the identity onto
Django's own theme variables. Diagram node/port colors and operational status
colors retain their meaning.

On the three workspaces, load tokens before component styles, then shell and
splitters, and **keep `dialog_theme.css` last among first-party stylesheets**.
The dialog tokens alias the shared page tokens. Native Contacts/External MCPs,
Voice/Mic, Catalog, jQuery UI, Usage, PDF progress and existing runtime dialogs
therefore share the same surfaces and controls. Continue/Save/Backup/Set are
primary; Cancel/Close retain the secondary appearance. DB button presentation
changes do not alter backup/restore handlers or mechanics.

The jQuery UI build does not guarantee that every footer button has a
`.ui-button` class. Theme the actual button-pane buttons too. Its overlay needs
explicit fixed viewport geometry and a layer above the expanded navigation;
otherwise a visually open modal can sit underneath the menu at high zoom.
The sweep found and repaired both conditions with real browser checks.
